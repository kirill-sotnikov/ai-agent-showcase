# AI Shopping Assistant

ИИ-ассистент для покупок: ищет товары в каталоге, отвечает на вопросы и управляет корзиной через диалог. Проект показывает полный цикл агентного приложения — от определения намерения и вызова инструментов до сохранения результата и проверки качества в Promptfoo.

В интерфейсе доступны чат, корзина и журнал выполнения с этапами обработки запроса и вызовами инструментов. На странице настроек можно редактировать каталог и профиль ассистента.

> **Скриншот приложения:** чат, корзина и журнал выполнения.

## Архитектура

Проект — TypeScript-монорепозиторий с тремя пакетами:

| Пакет              | Назначение                                           | Технологии                               |
| ------------------ | ---------------------------------------------------- | ---------------------------------------- |
| `packages/web`     | Интерфейс, состояние пользователя и WebSocket-клиент | Next.js, React, Zustand, vanilla-extract |
| `packages/service` | Сервер, оркестратор ИИ и инструменты                 | Fastify, WebSocket, OpenAI SDK           |
| `packages/shared`  | Общие контракты и правила работы с корзиной          | Zod, TypeScript                          |

Браузер обращается к Next.js, который проксирует WebSocket-запросы в Fastify. Сервер выполняет ИИ-workflow и передаёт события для журнала выполнения. Каталог, корзина, настройки и история сохраняются в `localStorage`; сервер работает без базы данных. Ключ OpenAI используется только на сервере.

### ИИ Агент

Оркестратор запускает Guard и Router параллельно, у каждой роли отдельный промпт. Инструменты покупок запускаются только после разрешения Guard и валидного результата Router. Спам или ошибка Guard отменяют незавершённую маршрутизацию; ошибка предварительного расчёта маршрута не переопределяет решение Guard о спаме. Guard, Router, Knowledge и Action используют модель из `OPENAI_MODEL`. Composer — обычная функция приложения без вызова модели.

```mermaid
flowchart TD
    Request[Сообщение пользователя] --> Guard["[AGENT] Guard: проверка запроса"]
    Request --> Router["[AGENT] Router: определение намерения"]
    Guard --> Gate{Guard разрешил и маршрут валиден}
    Router --> Gate
    Gate --> Knowledge["[AGENT] Knowledge: вопросы и диалог"]
    Gate --> Action["[AGENT] Action: команды и смешанные запросы"]
    Knowledge --> ReadTools["[TOOL] Необязательное чтение каталога и корзины"]
    ReadTools --> Answer[Текст ответа и showCart]
    Answer --> Validation[Проверка ссылок на товары]
    Action --> CartTools["[TOOL] Поиск и изменения черновика корзины"]
    CartTools --> ValidateCart[Проверка результата и изменений]
    ValidateCart -->|Корзина изменена| Commit[Сохранение в браузере и ACK]
    ValidateCart -->|Без изменений| ActionAnswer["[AGENT] Action: финальный текст"]
    Commit --> ActionAnswer
    Validation --> Composer["Composer: функция приложения без LLM"]
    ActionAnswer -->|showCart всегда true| Composer
    Composer --> Response[Ответ пользователю]
```

`[AGENT]` — агент на базе LLM; `[TOOL]` — группа доступных агенту инструментов. Этапы обработки без меток выполняются кодом приложения, включая Composer.

| Роль          | Ответственность                                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Guard**     | Проверяет сообщение на спам с учётом контекста диалога.                                                           |
| **Router**    | Различает вопрос, команду, смешанный запрос и обращение вне темы. При неоднозначности запрашивает уточнение.      |
| **Knowledge** | Пишет ответ обычным текстом; при необходимости использует инструменты чтения и выбирает `showCart`.               |
| **Action**    | Находит товары и меняет черновик корзины. После проверки и ACK формирует текст ответа; всегда показывает корзину. |
| **Composer**  | Принимает `{ text, showCart }`, передаёт текст в чат и добавляет представление корзины. Не вызывает LLM.          |

Инструменты чтения: `search_products`, `get_product`, `get_cart`, `choose_cheapest`. Для изменений доступны `add_to_cart`, `set_cart_quantity`, `remove_from_cart`. Поиск выполняется по ключевым словам и фильтрам; выбор минимальной цены рассчитывается в коде.

Модель выбирает инструменты через function calling и возвращает структурированные результаты. Шлюз инструментов проверяет аргументы через Zod, права роли и лимит вызовов. Прежде чем изменить товар, агент обязан получить его из каталога. Тексты промптов версионируются в [`packages/service/src/ai/prompts/v1`](packages/service/src/ai/prompts/v1).

Knowledge отвечает на сам вопрос: например, на вопрос о цвете достаточно «Лампа зелёного цвета». Приветствия, благодарности и вопросы о возможностях не требуют инструментов. Пустой список товаров больше не означает автоматически «ничего не найдено». Для вопроса Knowledge выбирает `showCart: true | false`; для Action оркестратор всегда устанавливает `showCart: true`, включая уточнения и ошибки.

Финальный вызов Action выполняется без инструментов после проверки результата и, при изменениях, подтверждения сохранения. Он получает историю, полученные товары, результаты инструментов, сохранённую корзину и квитанцию. При сбое генерации после сохранения приложение показывает текст квитанции.

В чат передаются обычный текст и необязательный снимок корзины. Браузер формирует его из сохранённого состояния: цены, количества и итог не берутся из текста модели. Снимки сохраняются вместе с сообщениями и не меняются при следующих покупках. Старые сообщения без новых полей остаются совместимыми.

Промпты требуют опираться на полученные данные. Код проверяет идентификаторы товаров, права инструментов и изменения корзины, но не доказывает достоверность каждого утверждения свободного текста — для этого нужны проверки качества ответов. `choose_cheapest` находит минимум среди переданных товаров; поиск ограничен десятью результатами, поэтому неполную выборку нельзя выдавать за весь каталог.

## Оценка качества с Promptfoo

**Promptfoo** подключён через TypeScript SDK. Он запускает сценарии через настоящий оркестратор и шлюз инструментов, собирает результаты и позволяет сравнивать прогоны в локальном интерфейсе.

В наборе **40 сценариев**: поиск и фильтрация по цене, выбор самого дешёвого товара, изменения корзины, уточнения, отсутствующие характеристики, пустой каталог, prompt injection, сбои workflow, текстовые ответы на обычные вопросы, показ корзины и сравнение цен с учётом предыдущего сообщения.

Проверки написаны на TypeScript. Они оценивают текст ответа, показ корзины, отсутствие лишних вызовов инструментов, итоговую корзину, найденные товары, уточнения, коды ошибок и порядок подтверждения сохранения. Браузерные тесты проверяют текстовые ответы и сохранение снимков корзины после изменений и перезагрузки. В отчёт также попадают вызванные инструменты, время выполнения, расход токенов и оценка стоимости для реальной модели.

```sh
# Запуск тестов
yarn eval:live

# Открыть историю и результаты прогонов
yarn eval:view
```

## Запуск

Требуются **Node.js 24+** и **Yarn 4.18.1** (версия закреплена в `package.json`).

```sh
corepack enable
corepack yarn install --immutable
cp .env.example .env
```

Укажите в `.env` значения `OPENAI_API_KEY` и `OPENAI_MODEL`, затем запустите приложение:

```sh
yarn dev
```

Откройте [localhost:3000](http://localhost:3000). Fastify запускается на порту `3001`. Модель должна поддерживать structured outputs, function calling и `reasoning.effort: "none"`, который задан в адаптере.

Для знакомства без API-ключа:

```sh
yarn dev:fake
```

Этот режим использует детерминированный парсер английских запросов и доступен для разработки и тестов. Примеры:

- `Find a lamp under $50 and add the cheapest one.`
- `Add two of the blue mugs.`
- `Remove one blue mug.`

Остальные параметры сервера и необязательных Telegram-уведомлений перечислены в [`.env.example`](.env.example).
